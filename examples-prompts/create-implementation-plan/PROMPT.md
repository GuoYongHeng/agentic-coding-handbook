# AI 智能编码实现计划生成器

## 背景
我需要你帮助我为一个软件功能或用户故事创建详细的实现计划，采用"智能编码"方法。这涉及利用 AI 将需求分解为可管理的、可测试的模块，这些模块可以被逐步构建和验证。

## 第一步：需求澄清
首先，通过聚焦的对话帮助我细化和明确需求：

1. 每次只询问一个具体的、相关的问题
2. 利用每个答案加深对项目需求的理解
3. 持续提出针对性问题，直到覆盖以下所有方面：
   - 核心功能和特性
   - 技术架构
   - 数据模型和关系
   - 用户体验需求
   - 集成点
   - 性能预期
   - 边界情况和错误处理
   - 安全考量

## 第二步：完整规格说明
需求明确后，创建完整的规格说明文档（spec.md），包括：

1. **执行摘要**：功能目的和目标的简洁概述
2. **功能需求**：
   - 核心功能和用户工作流
   - 界面需求和交互模式
   - 性能预期和约束
3. **技术规格**：
   - 架构设计和组件关系
   - 技术栈推荐及理由
   - 数据模型、Schema 和关系
   - API 规格（如适用）
   - 与外部系统的集成点
4. **实现注意事项**：
   - 错误处理策略
   - 边界情况及其解决方案
   - 安全需求
   - 可扩展性考量
5. **测试策略**：
   - 测试方法和覆盖率预期
   - 验收标准

## 第三步：实现规划
将规格说明分解为增量式开发计划：

1. 起草高层次蓝图，概述项目范围和主要组件
2. 将蓝图划分为相互递进的逻辑里程碑
3. 将每个里程碑分解为具体的实现任务，这些任务应：
   - 专注于单一职责
   - 足够小，可以自信地实现和测试
   - 足够大，能提供有意义的进展
   - 与之前的工作相关联
4. 为每个任务创建具体的编码提示词，该提示词应：
   - 清晰说明需要实现的内容
   - 根据需要引用之前的代码
   - 包含测试要求
   - 说明与现有组件的集成方式

## 第四步：开发路线图
生成两个关键输出：

1. **prompt_plan.md**：用于 Cursor、Claude Code 等代码生成工具的逐步提示词
   ```markdown
   # [功能名称] 实现提示词
   
   ## 设置和前置条件
   
   ```prompt
   [描述需要首先设置的内容]
   
   请为 [功能] 设置初始项目结构，包含以下内容：
   - [具体的框架/库需求]
   - [所需的文件结构]
   - [配置需求]
   
   生成以下文件：
   1. [文件名] - [用途]
   2. [文件名] - [用途]
   
   包含验证以下内容的测试：
   - [测试标准]
   ```
   
   ## 里程碑 1：[里程碑名称]
   
   ### 任务 1.1：[任务名称]
   
   **背景：** [说明此任务如何融入整体项目]
   
   ```prompt
   [详细描述需要实现的代码]
   
   需求：
   - [具体需求]
   - [具体需求]
   
   这应该通过 [集成说明] 与 [现有组件] 集成。
   
   包含验证以下内容的测试：
   - [测试标准]
   - [测试标准]
   ```
   
   ### 任务 1.2：[任务名称]
   
   ...
   
   ## 里程碑 2：[里程碑名称]
   
   ...
   
   ## 集成和最终测试
   
   ```prompt
   [最终集成步骤]
   
   请实现验证以下内容的集成测试：
   - [集成测试标准]
   - [集成测试标准]
   ```
   ```

2. **todo.md**：开发期间可逐项勾选的全面、可操作的任务清单
   ```markdown
   # [功能名称] 开发清单
   
   ## 设置和前置条件
   - [ ] 设置项目结构
   - [ ] 配置开发环境
   - [ ] 安装所需依赖
   
   ## 里程碑 1：[里程碑名称]
   
   ### 核心实现
   - [ ] 任务 1.1：[清晰、可操作的描述]
     - [ ] 实现 [具体组件/函数]
     - [ ] 为 [具体组件/函数] 编写测试
     - [ ] 确保测试通过
   
   - [ ] 任务 1.2：[清晰、可操作的描述]
     - [ ] 实现 [具体组件/函数]
     - [ ] 为 [具体组件/函数] 编写测试
     - [ ] 确保测试通过
   
   ### 审查与重构
   - [ ] 重构 [具体组件] 以提升 [性能/可读性/等]
   - [ ] 确保重构后所有测试仍然通过
   
   ## 里程碑 2：[里程碑名称]
   
   ### 功能实现
   - [ ] 任务 2.1：[清晰、可操作的描述]
     - [ ] 实现 [具体组件/函数]
     - [ ] 为 [具体组件/函数] 编写测试
   
   ...
   
   ## 最终集成
   - [ ] 集成所有组件
   - [ ] 运行全面测试套件
   - [ ] 验证所有验收标准已满足
   
   ## 部署准备
   - [ ] 更新文档
   - [ ] 准备发布说明
   - [ ] 最终代码审查
   ```

## 实现原则
在整个规划过程中，强调：
- 测试驱动开发（TDD）方法
- 通过可验证的步骤实现增量进展
- 组件间的清晰依赖链
- 面向整体的小型、专注任务
- 在逻辑里程碑处进行集成测试
